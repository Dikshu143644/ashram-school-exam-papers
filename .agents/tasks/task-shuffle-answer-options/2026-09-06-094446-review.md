# Shuffle correct-answer positions across all exam papers (v1)

The exam papers had the correct choice sitting at option A in nearly every question, making the whole site trivially gameable. This change moves each correct answer to a new position spread across A/B/C/D (and A/B/C for three-option fill-ins), re-letters the options sequentially after reordering, and rewrites the Match-the-following Column-B ordering so the naive 1→A, 2→B, 3→C, 4→D pairing is never the answer while every item still maps to its correct meaning. It touches the AI paper (HTML + Markdown + answer key), all ten standards in `index.html`, and the mirrored Std-1/Std-2 blocks in the Computer markdown, keeping every representation of the same question in agreement. An `audit-map.md` under the task directory records the intended old→new position for every block and is the source of truth the implementation was checked against.

Watch for: (1) `index.html` has no embedded answer key, so its correctness rests entirely on the audit-map assumption that the pre-change first option was the correct one — unverifiable from the site itself (confirmed, inherent to the task). (2) The AI paper's HTML carries no visible correct-answer marker; answer correctness lives only in `AI_Exam_Model_Answer_Key.md`, which must stay in lockstep with the reordered options (confirmed, verified in sync this pass). (3) Three match tables (Std 6, 9, 10) have a fifth row (E) that was left in place; the last item lands on its straight-line letter, which is unavoidable once the other four are fixed (confirmed, semantically correct).

**Verdict**: APPROVED

## High-level view

The reordering is a pure positional permutation: option and Column-B *text* is preserved verbatim, only sequence and leading letters change. A diff-wide check confirms no question stems, CSS classes, or structural markup were altered — every changed line is an option row, a match Column-B cell, or an answer-key entry.

Correctness is anchored differently per file. The AI paper is authoritative from `AI_Exam_Model_Answer_Key.md`, and all ten MCQ letters (C,D,B,A,C,B,D,D,B,C), five fill-in letters (C,B,A,D,B), and the match code (AI→A, Input→C, ML→D, Output→B) were verified to point at the correct-answer text at its new position in both the HTML and the MD. `index.html` has no key, so its correctness inherits the audit-map's "first option was correct" premise; the implemented positions match the plan exactly for all ten papers.

Consistency across mirrored representations holds: `index.html` Std-1/Std-2 MCQ, fill-in, and match orderings are identical to the Computer markdown, and the AI HTML/MD option orderings agree question-for-question. Label integrity is clean — all 72 `options-list` blocks and all 10 match grids carry gap-free, duplicate-free sequential labels. Genuine "All of the above" answers were kept at D rather than forced elsewhere.

### Positional permutation with text preserved

Every edit in the diff is a reordering of existing option text plus a relabel of the leading letter; no answer text was reworded, added, or dropped. A scan of all changed lines across the five content files finds nothing outside option rows, match Column-B cells, and answer-key cells — question stems, `q-en` translations, CSS classes, and table structure are untouched.

### AI paper: answer correctness lives only in the key file

The AI paper spans `AI_Exam_Question_Paper.html`, `AI_Exam_Question_Paper.md`, and `AI_Exam_Model_Answer_Key.md`, and all three moved together. Checked against the authoritative key:

```
MCQ    Q1..Q10  -> C D B A C B D D B C
Fill   Q11..Q15 -> C B A D B
Match           -> AI→A  Input→C  ML→D  Output→B
```

For each MCQ the correct-answer text now sits at exactly the key's letter in both the HTML `options-grid` and the MD checkbox list (e.g. Q2 "Artificial Intelligence" moved A→D; Q7 "Result produced after processing" moved A→D), and the unchanged questions still align (Q4 at A, Q8 "All of the above" at D, Q9 at B). The match code A,C,D,B places no item on its straight-line letter.

The HTML option rows carry an empty `opt-check` span and the MD uses blank `[ ]` checkboxes, so neither rendered paper reveals the answer — correctness is expressed only in the key file. It is in sync this pass, but that makes the key a single point of truth: a future reorder that forgets it would desync silently with no in-file signal.

### index.html: plan-anchored, no in-site key

`index.html` contains all ten standards but no answer key, so the correct answer is defined externally by `audit-map.md` (built on the confirmed authoring pattern that the original first option was correct). The implemented MCQ positions reproduce the plan for every paper — verified end to end for Std 1 (B,D,C,A,C), Std 2 (C,A,D,B,C), through Std 10 (C,D,A,B,A,C,A,D,A,B). Because there is no key in the artifact itself, this file cannot be self-checked; its correctness is only as good as the audit map, and that is the one place where a silent error could not be caught by internal consistency alone.

### Match sections: semantic pairing preserved, straight line broken

All ten match grids were re-lettered so the correct pairing is never 1→A, 2→B, 3→C, 4→D, while each item still resolves to its correct meaning. For the four-item tables this is fully broken (e.g. index Std-1 → Monitor→C, Keyboard→D, Mouse→B, CPU→A; AI → AI→A, Input→C, ML→D, Output→B).

Three tables (Std 6, 9, 10) carry a fifth row E that predates this change and was left in place. The first four items are de-linearized, but the fifth necessarily maps to E once the others are placed — Std 6 AI→E, Std 9 AI→E, Std 10 Mouse→E. Each is still the semantically correct pair, so this is a forced-final-position artifact, not a missed shuffle.

### Cross-representation consistency and label integrity

`index.html` Std-1/Std-2 and the Computer markdown carry identical option orderings and identical match Column-B orderings after the change (Std-1 match A.Processing/B.Selecting/C.Seeing/D.Typing in both; Std-2 match A.Clicking/B.Screen/C.Typing/D.Processing in both). The Std-2 fill-in and True/False blocks were left unchanged in both files, so they stay aligned. A programmatic pass over `index.html` confirms all 72 `options-list` blocks and all 10 match grids have sequential, gap-free, duplicate-free labels (A–D / [A]–[C] for options, A–D or A–E for Column B).

### Scope

The task is content-only and stays independent of the separate deploy branch — no `vercel.json`, `render.yaml`, or other deployment config was touched. The task-state files under `.agents/tasks/task-shuffle-answer-options/` are process artifacts, not site content. No unrelated changes are bundled in.
